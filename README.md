# Информационная система и база данных бухгалтерской отчетности организаций (ФГБУ ГМЦ Росстата)

Прототип государственной информационной аналитической системы сбора, нормализации, хранения и анализа годовой бухгалтерской (финансовой) отчетности организаций (аналог **ГИР БО**), разработанный по техническому заданию **ФГБУ «Главный межрегиональный центр обработки и распространения статистической информации Федеральной службы государственной статистики» (ГМЦ Росстата)**.

## 🏛 Назначение системы

Система предназначена для централизованного приема, валидации, дедупликации и аналитической обработки годовой бухгалтерской (финансовой) отчетности юридических лиц РФ, поступающей в форматах ФНС России:
* **КНД 0710099 (Версия формата `5.08`)** — полная бухгалтерская (финансовая) отчетность (Формы 1–5 по Приказу Минфина России № 66н).
* **КНД 0710096 (Версия формата `5.03`)** — упрощенная бухгалтерская (финансовая) отчетность субъектов малого предпринимательства.
* Универсальные шаблоны обмена данными в форматах **Excel (`.xlsx`)** и **JSON (`.json`)**.

## 🗄 Архитектура базы данных (3 слоя, 12 таблиц)

Эталонная схема БД реализована в [`db/init.sql`](db/init.sql) (PostgreSQL 15) и в ORM-моделях [`app/models.py`](app/models.py) с прозрачной поддержкой как **PostgreSQL 15**, так и локального движка **SQLite** (для мгновенного запуска без поднятия контейнеров).

### Слой 1. Справочники и метаданные (7 таблиц)
1. **`regions`** — Справочник субъектов РФ (`code` 2 символа, наименование региона, федеральный округ).
2. **`industries`** — Иерархический справочник видов экономической деятельности **ОКВЭД2** (`parent_id` для дерева разделов/классов/подклассов, буквенный `section`).
3. **`units`** — Справочник единиц измерения **ОКЕИ** (`383` — рубль, `384` — тыс. руб., `385` — млн руб.) с коэффициентом пересчета `to_rub`.
4. **`report_forms`** — Справочник форм отчетности (`F1` — Бухгалтерский баланс, `F2` — Отчет о финансовых результатах, `F3` — Отчет об изменениях капитала, `F4` — Отчет о движении денежных средств, `F5` — Пояснения к балансу).
5. **`indicators`** — Канонический словарь показателей по **Приказу Минфина России № 66н** (коды строк `1100`..`5400` и агрегированные коды упрощенной отчетности `UPR_KREDIT`, иерархия `parent_id`, признаки `is_total` и `is_aggregated`).
6. **`indicator_sources`** — **Мост XPath-маппинга** между различными версиями XML-форматов ФНС (`5.03` и `5.08`) и единым каноническим словарем `indicators`.
7. **`value_slices`** — Измерения (срезы) матричных форм отчетности (`total`, `ustav`, `dobav`, `rezerv` для Формы 3; `operational`, `investing`, `financing` для Формы 4; `original`, `depreciation`, `residual` для Формы 5).

### Слой 2. Ядро учета отчетности (4 таблицы)
8. **`organizations`** — Карточка отчитывающейся организации (ИНН, ОГРН, ОКПО, ОКОПФ, ОКФС, ОКВЭД2, регион, категория субъекта МСП, неструктурированный и нормализованный JSON-адрес `address_norm`, тип подписанта).
9. **`report_packages`** — Комплект бухгалтерской отчетности за отчетный период (КПП, год, код периода `34`, номер корректировки `correction_no`, КНД, версия формата, программа-генератор, JSON-сведения о подписанте, флаг актуальности `is_current` и ссылка на заменяющий пакет `superseded_by`).
10. **`reports`** — Конкретный раздел (форма `F1`–`F5`) внутри комплекта отчетности с привязкой к ОКУД и единице измерения ОКЕИ (`unit_code`).
11. **`report_values`** — Фактические значения показателей с поддержкой срезов `slice_id`, отчетной даты `as_of`, признака сравнительного периода `is_comparative` (`СумОтч` / `СумПрдщ` / `СумПрдшв`) и строгим `CHECK`-ограничением целостности статуса (`reported`, `zero`, `not_disclosed`, `not_applicable`).

### Слой 3. Служебный контур (1 таблица)
12. **`import_files`** — Журнал импорта файлов для обеспечения **строгой идемпотентности по SHA-256** (`sha256 UNIQUE`, имя файла, исходная кодировка `UTF-8` / `windows-1251`, сырой XML, статус обработки и JSON-диагностика ошибок).

## 🔗 Механизм XPath-маппинга (`indicator_sources`) для версий XML 5.03 и 5.08

В форматах ФНС структура XML-дерева для полной (`5.08`) и упрощенной (`5.03`) отчетности существенно различается (например, в `5.08` запасы лежат в `/Документ/Баланс/Актив/ОбА/Запасы`, а в `5.03` — напрямую в `/Документ/Баланс/Актив/Запасы`).

Вместо жесткого кодирования (hardcode) путей в коде парсера, модуль [`app/importer.py`](app/importer.py) считывает правила привязки из таблицы `indicator_sources` для соответствующей `format_version` и динамически извлекает атрибуты `СумОтч`, `СумПрдщ` (`СумПред`) и `СумПрдшв`, приводя любые версии XML к единому каноническому словарю показателей `indicators`.

## 🚀 Быстрый запуск проекта

### Вариант 1. Мгновенный локальный запуск за 30 секунд (SQLite по умолчанию)

Проект настроен так, что по умолчанию используется локальная БД `sqlite:///./rosstat_gmc.db`. Внешний сервер PostgreSQL не требуется.

```bash
# 1. Установка зависимостей
pip install -r requirements.txt

# 2. Инициализация БД, сидирование 25 организаций (2023-2025 гг.) и генерация sample_data/
python -m app.seed

# 3. Запуск веб-сервера FastAPI
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

После запуска откройте в браузере:
* **Аналитический дашборд ГМЦ Росстата:** [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
* **Интерактивная документация OpenAPI (Swagger):** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

---

### Вариант 2. Запуск с PostgreSQL 15 через Docker Compose

```bash
# 1. Поднять контейнер PostgreSQL 15 (автоматически выполнит db/init.sql)
docker-compose up -d

# 2. Задать переменную окружения DATABASE_URL и заполнить БД демо-данными
# На Windows (PowerShell):
$env:DATABASE_URL="postgresql://rosstat_user:rosstat_password@localhost:5432/rosstat_gmc"
python -m app.seed

# 3. Запустить сервер
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
